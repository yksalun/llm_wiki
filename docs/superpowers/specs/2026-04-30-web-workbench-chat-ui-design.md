# Web 工作台与问答界面整理设计

日期：2026-04-30

## 背景

当前 Web 项目工作台已经能加载项目、浏览文件、展示分析信息，并通过 Web API 代理桌面端问答服务。用户本地测试后确认问答已经走桌面端回答，但现有界面仍有几处信息架构和体验问题：

- “洞察”命名不够直观，需要改为“分析”。
- “目标”和“结构”与“文件”能力重复，独立入口会让用户误解为不同功能。
- “项目信息”作为独立 tab 过重，而“概览”当前内容又包含目标/结构快捷入口，和新的信息架构冲突。
- 文件树默认全部展开，项目文件较多时页面会被拉长。
- 问答区当前是手写消息列表，缺少成熟 AI 问答界面应有的消息线程、Markdown 渲染和常规交互细节。

本设计聚焦 Web 端 UI 和前端接入层，不修改桌面端项目，也不改变桌面端问答业务逻辑。Web 端继续作为前端和轻量代理使用，问答实现、历史记录和最终结果仍由桌面端服务负责。

## 目标

1. 精简工作台 tab，只保留用户能清晰理解且不会重复的入口。
2. 将项目元信息放到“概览”页，移除独立“项目信息”页。
3. 将“洞察”显示名改为“分析”。
4. 文件树支持目录折叠，避免大项目默认铺开所有文件。
5. 问答界面采用成熟 AI 聊天 UI 方案，支持流式回答、Markdown 渲染、历史会话、消息列表和引用文件打开。
6. 保持 Web 服务端问答逻辑为桌面端 API 代理，不在 Web 端引入自己的问答业务逻辑。

## 非目标

- 不修改桌面端项目代码。
- 不改变桌面端问答 API 的语义、历史记录存储方式或回答生成逻辑。
- 不把当前桌面端自定义 SSE 协议改造成 Vercel AI SDK 标准协议。
- 不重新设计整个 Web 应用视觉系统。
- 不移除“分析”能力本身，只改显示文案和保留当前功能入口。

## 信息架构

项目工作台顶部 tab 调整为：

- 概览
- 问答
- 分析
- 文件

移除以下 tab：

- 目标
- 结构
- 项目信息

`purpose.md` 和 `schema.md` 不再有独立 tab，也不再由概览页快捷卡片打开。它们仍然作为普通项目文件存在，用户可在“文件”页通过文件树打开。

底层类型可以暂时保留 `Purpose`、`Schema`、`Project Info` 枚举兼容旧测试和潜在后端响应，但实际项目详情返回的 `sections` 应只包含新的四个入口。前端渲染时也应以允许列表做兜底过滤，避免旧数据把已移除入口显示出来。

## 概览页设计

“概览”页替换为原“项目信息”内容，展示项目的结构化元信息：

- 项目名称
- 项目编号
- 状态
- 访问模式
- 写入权限
- 重任务运行时
- 桥接状态
- 已跟踪重任务
- 目标文件是否存在
- 结构文件是否存在
- 知识库目录是否存在
- 原始资料目录是否存在
- 工作区入口列表
- 文件树条目数

原概览页中的目标、结构、完整文件浏览器、知识库快捷入口会被移除，避免与“文件”页重复。

## 文件树设计

文件树目录节点改成可展开/折叠：

- 默认只展示根层级。
- 点击目录行切换展开状态。
- 展开目录使用 `ChevronRight` / `ChevronDown` 或同类图标表达状态。
- 文件节点保持点击打开文件。
- 当通过搜索、问答引用、分析引用打开某个文件时，文件树应自动展开该文件的父目录链，让选中文件可见。
- 如果目录被折叠，子节点不渲染，避免大项目初始页面过长。
- 当前文件的选中状态和加载状态保持不变。

展开状态建议保存在 `FileTree` 组件内部。组件通过 `selectedPath` 监听当前选中文件，自动补齐父级目录展开状态。这样不会污染全局工作台 store，也不会影响文件编辑草稿保护逻辑。

## 问答 UI 方案

问答界面采用 `assistant-ui`：

- `@assistant-ui/react` 提供成熟聊天线程、消息、输入区和运行时抽象。
- `@assistant-ui/react-markdown` 负责 Markdown 渲染。
- 使用 assistant-ui 的外部状态/自定义后端接入能力，适配当前桌面端桥接 API。

布局采用已确认的左侧会话栏：

- 左侧：新会话按钮、历史会话列表、当前会话高亮、加载/禁用状态。
- 右侧：消息线程、流式回答、Markdown 正文、引用文件列表、输入区、停止生成按钮。
- 移动端或窄屏可让会话栏堆叠在消息线程上方，避免横向溢出。

需要保留的行为：

- 初始化时加载桌面端会话列表。
- 如果没有会话，自动创建新会话。
- 选择会话时加载该会话历史消息。
- 发送问题时先追加用户消息，再显示助手消息流式内容。
- 桌面端返回最终消息后，用最终消息替换流式临时消息或追加最终消息，避免重复显示。
- 停止生成时中止当前请求，并清理流式临时状态。
- 引用文件仍以按钮或引用卡片展示，点击后调用 `onOpenFile(relativePath)`。
- 项目切换时中止旧请求，避免旧项目响应污染新项目界面。

## 数据流

问答数据流保持现状：

1. Web 前端调用 `/api/projects/{projectId}/question/conversations` 加载或创建会话。
2. Web API route 通过 `desktop-bridge-client` 代理到桌面端服务。
3. Web 前端调用 `/messages` 加载历史消息。
4. Web 前端调用 `/messages/stream` 发送问题并接收 SSE。
5. Web 客户端解析桌面端桥接事件：
   - `token`：追加到当前流式助手消息。
   - `references`：更新当前助手消息引用。
   - `done`：写入最终助手消息。
   - `error`：展示错误状态。
6. assistant-ui 只负责 UI 和消息线程渲染，不接管桌面端服务协议。

Web 服务端不新增问答存储，不自行生成回答，不改变历史记录来源。

## 错误处理

- 桌面端桥接不可用：问答面板展示中文错误提示，保留重试或重新进入页面后的恢复能力。
- 会话加载失败：不显示空白聊天页，展示错误提示。
- 消息发送失败：保留用户输入或允许用户重新输入，避免静默失败。
- 流式过程中报错：停止流式状态，展示错误提示，避免输入框永久禁用。
- 项目切换或组件卸载：中止所有进行中的会话、消息和流式请求。
- 文件打开失败仍由现有文件面板错误提示承接。

## 测试计划

单元/组件测试：

- `display-labels`：`Insights` 显示为“分析”。
- `project-registry` 或工作台渲染：项目 sections 只出现“概览 / 问答 / 分析 / 文件”。
- `ProjectWorkbench`：不再显示“目标 / 结构 / 项目信息”tab。
- `ProjectOverview`：显示项目元信息，包含访问模式、写入权限、桥接状态、文件树条目数。
- `FileTree`：目录默认折叠，点击展开/折叠，选中文件路径触发父目录自动展开。
- `ProjectQuestionPanel`：加载历史会话和消息、无会话时创建新会话、切换会话、发送流式消息、停止生成、引用文件打开。
- Markdown 渲染：助手消息中的 Markdown 能渲染为结构化内容，而不是纯文本。

命令验证：

- `npm run typecheck`
- `npm run test -- --runInBand` 不适用于 Vitest，本项目使用 `npm run test`。
- 必要时针对改动文件运行 Vitest 过滤用例。

浏览器验证：

- 打开项目详情页，确认 tab 精简和中文文案。
- 查看概览页项目元信息。
- 在“文件”页展开/折叠目录并打开文件。
- 在“问答”页查看历史、发送问题、观察流式输出和 Markdown 渲染。

## 实施边界

本轮实现可以修改：

- Web 工作台组件和相关测试。
- Web 文件树组件和相关测试。
- Web 问答面板组件和相关测试。
- Web 展示文案映射。
- Web `package.json` / lockfile，用于加入 `assistant-ui` 和 Markdown 渲染依赖。

本轮不修改：

- 桌面端问答实现。
- 桌面端本地 HTTP 服务行为。
- Web API route 的业务语义；仅在必要时做类型或错误处理适配。

## 设计决策

选择 `assistant-ui` 而不是 Vercel AI Elements，是因为当前系统的核心约束是“桌面端是服务器，Web 端只是前端和代理”。assistant-ui 的外部状态/自定义后端接入方式更适合保留当前桌面端桥接协议。AI Elements 更贴近 shadcn 和 Vercel AI SDK，但如果直接使用会倾向于把流协议改造成 AI SDK 形态，超出了本轮目标。

选择左侧会话栏，是因为它最符合常规 AI 产品的历史记录模型，也能完整呈现桌面端已有的多会话能力。顶部选择或隐藏历史更节省空间，但会降低历史记录的可发现性。
